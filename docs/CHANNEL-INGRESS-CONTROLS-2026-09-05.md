## Implemented in source

- Telegram, WhatsApp, Slack and Twilio authenticate first, save each accepted event and its original identity before HTTP success, and return a sanitized 503 if storage fails. TNZ already uses this shared durable-save path. Verification challenges and rejected/non-message events retain their inline responses. `after()` only wakes saved work; there is no raw-event fallback. Slack's acknowledgement latency target still needs a real-provider timing test.
- The app and worker use the same one-at-a-time atomic inbox claim. Processing requires `CapturedInbound`, never a raw provider event or a new sender lookup. Worker conversation draining is no longer limited to the TNZ configuration or the commands toggle. The global messaging gate still applies; Apple ingress remains reserved/disabled.
- New service-only **security-invoker** `apply_channel_inbound_control` performs code consumption/device transfer, current STOP/conversation-close opt-out, human handoff and inbound timestamp updates in one short transaction. It checks the originally captured account, user, generation, link revision and channel scope. Current opt-out works while account automation is paused; stale STOP cannot disconnect a replacement binding. This does not enable processing through the global messaging-off release gate.
- Code transfer checks expiry after lock waits and again after deleting a previous destination. Failure rolls back the deletion. Code consumption and handoff return the actual new database-managed revision in an immutable inbox control receipt; the original arrival binding is never rewritten. The old multi-statement `consumeLinkCode` path is removed.
- Service-only **security-invoker** `verify_channel_inbound_binding` checks link/account/member/scope/pause in one database call, with short row locks. This replaces serial REST preflights; it is **not a lock across model/provider I/O** or a substitute for atomic persistence and outbound claims.
- Captured generation reaches command dispatch, approval resolution and the default channel reply pipeline. Preflights surround consequential awaits. Identity failures propagate through ordinary model-error handling and optional reply-shortening; no stale fallback is sent or learning hook started after a detected failure. The existing asynchronous learning hook still needs its own complete delayed-writer protection.
- The consumer no longer releases legacy WhatsApp queue rows on a new inbound message: those rows lack original generation/link revision. A generation-bound outbox consumer is still required. Outbound preflights added here do not claim durable pre-send delivery protection.
