## Implemented boundary and screens

- `/ops` ports the supplied ops sidebar, Clients, Client detail, Setup pipeline and Run monitor into the existing Next.js application. It is a read-only management surface, not customer impersonation. Revenue/goal-progress estimates, fabricated stage ages, automatic retries and enabled-as-running claims are not copied from the prototype.
- GET `/api/ops` validates the current Supabase Auth user and confirmed email, refuses anonymous identities and has no demo fallback. Only that server actor reaches the RPC; injected query/header actor IDs and malformed/duplicate selections are refused. No customer membership is accepted as operator authority.
- Service-only `ops_account_access` grants read scope explicitly per operator and account. RLS is enabled, public/anonymous/authenticated table privileges and RPC execution are revoked. There is no browser endpoint to create/revoke scopes or change a client. `read_ops_console` is SECURITY INVOKER / STABLE: authorization and projection use one statement snapshot, and revoked/expired scopes fail closed.
- Projection includes actual member counts, selected connector/read metadata, enabled switches, current-generation draft/run/receipt headers and member-bound verified channel timestamps. It excludes credentials, link codes, customer chat, raw run snapshots, artifact bodies and receipt payloads. Exact IDs distinguish both AVGAR records. No client merge, invite or customer role change.
- Counts on Clients cover current-context records for each listed account; run-monitor counts cover its bounded result window. Account lists and each history list are capped at 100 with explicit window notices. Older-history/account pagination, full operator work preview, delivery/cost/stall monitoring and governed recovery actions remain unfinished. Cross-client read auditing beyond platform request logs also remains open.
- Setup stages are conservative derived checks: Needs identity, Needs connections, Needs verification, Paused, Review runtime. None certifies a client Live. Dated successful reads are not claimed fresh; all read timestamps are shown in UTC. Stored channel verification is not successful message delivery.
- UI handles loading, failure, unauthorized access, exact client selection, search, filters, hash reload/back and small screens. Failure or revoked access on refresh removes previously visible records. No polling loop; refresh and returning to a visible tab perform a current read.
